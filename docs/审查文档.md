## 结论

当前机器上复现的是“Codex Desktop / ChatGPT Desktop 启动并托管的工具子进程没有及时回收”，不是单个 `uv.exe` 自身泄漏。

进程树证据显示，`ChatGPT.exe -> codex.exe` 下挂着多批重复 MCP/工具服务，包括 `uv.exe`、`python.exe`、`node.exe`、`pwsh.exe`、`Open Design.exe`、`node_repl.exe`。这些旧子进程在 5 秒采样窗口内 CPU 增量为 0，且已存活十几分钟，特征更接近空转残留。

图片/base64 日志问题在本机存在痕迹，但没有达到截图中 `.codex/sessions` 数百 GB 的灾难规模。本机更突出的存储膨胀是 `.codex/logs_2.sqlite`，约 12.88 GB。

当前本地修复版确实接管了启动入口，但接管的是旧来源包副本：快捷方式指向 `C:\Users\32893\AppData\Local\Programs\Codex-NTFS-Fix\baseline\app\ChatGPT.exe`，该副本来源为官方 `OpenAI.Codex_26.707.8479.0`；系统注册的官方包已经更新到 `OpenAI.Codex_26.721.4979.0`。因此，当前修复版存在“官方更新后未自动迁移补丁”的版本漂移风险。

## 进程生命周期审查

审查时观察到的重复子进程形态：

| 进程族 | 观察 | 判断 |
|---|---|---|
| `uv.exe -> python.exe -> bocha-search-mcp.exe` | 多套重复链路同时存在 | MCP 服务按会话/线程重复拉起，未及时回收 |
| Hermes / Open Design MCP `node.exe` | 多套 `api` / `devices` / `use` 服务重复存在 | MCP 服务未复用或未在任务完成后关闭 |
| `node_repl.exe` | 多套 Codex 内置 node REPL 残留 | 工具运行时生命周期需要 watchdog |
| `pwsh.exe` / `node.exe` 命令执行进程 | 多套重复存在，旧进程 CPU 空转 | 命令执行后 descendant tree 未闭环释放 |

优先根因判断：

1. Codex Desktop / app-server 对工具子进程树缺少可靠生命周期收束。
2. MCP 服务粒度偏细，可能按打开的 chat/thread 重复启动，未跨线程复用。
3. Windows 下 descendant process 继承 stdout/stderr/stdio 句柄时，父进程退出和任务完成不一定能释放整棵树。
4. 当前本地修复版主要缓解早前 NTFS/启动路径问题，未覆盖子进程回收。

## 图片与日志膨胀审查

用户提供的截图描述了社区案例：图片以 Base64 写入 `.codex/sessions/*.jsonl`，压缩/上下文继承/子代理分叉会重复复制这些图片 payload，导致会话日志膨胀到数百 GB。

本机检查结果：

- 最大 20 个 session jsonl 中确实存在 `data:image` / `;base64,` 标记。
- 当前本机未复现单图十几万次重复；最大 jsonl 约 86.96 MB。
- `.codex/logs_2.sqlite` 已达到约 12.88 GB，是当前本机更大的存储风险。

判断：图片/base64 问题属于高风险已知问题，但本机当前更需要先处理日志数据库体积、history cap、图片外置化与 compact 去重策略。

## 官方更新与补丁接管审查

用户提出的要求是：本地补丁作为“壳子”接管启动，但官方版本更新时，既不影响官方包内容，又要让补丁继续生效。

建议架构：

```text
Start Menu shortcut
  -> ChatGPT-Fix launcher
      -> discover latest registered OpenAI.Codex Appx package
      -> compare SourcePackageVersion and package hashes
      -> prepare isolated side-by-side runtime copy
      -> apply launcher/runtime mitigation only to isolated copy
      -> start isolated ChatGPT.exe
      -> watchdog tracks launched process tree
      -> on task/app exit, reclaim owned MCP/uv/node/python/pwsh descendants
```

关键原则：

- 不修改 `C:\Program Files\WindowsApps\OpenAI.Codex_*`。
- 不替换官方包注册状态。
- 快捷方式只指向本地 launcher，不直接指向某个固定旧版本副本。
- 每次启动都发现最新官方包版本，避免当前这种 `26.707.8479.0` 副本继续运行而官方已是 `26.721.4979.0` 的漂移。
- 补丁只作用于隔离副本、启动参数、环境变量或 wrapper watchdog。
- 为每个隔离副本记录来源版本、源包 hash、补丁版本、安装时间、回滚路径。
- watcher 只回收自己启动且超过安全条件的 descendant processes，避免误杀用户手动打开的终端或活跃任务。
